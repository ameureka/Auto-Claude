## 一、原方案问题诊断

### 1.1 核心缺陷

原方案存在**根本性设计错误**：

```
原方案假设: claude-agent-sdk 会读取 ANTHROPIC_API_KEY
实际行为:   claude-agent-sdk 只读取 CLAUDE_CODE_OAUTH_TOKEN
结论:       原方案的 apply_auth_env() 分离注入设计无效
```

**代码证据** (`apps/backend/core/client.py:136-138`):
```python
oauth_token = require_auth_token()
# Ensure SDK can access it via its expected env var
os.environ["CLAUDE_CODE_OAUTH_TOKEN"] = oauth_token  # SDK 唯一读取点
```

### 1.2 原方案失效场景

| 场景 | 原方案行为 | 实际结果 |
|------|-----------|----------|
| API Key 用户 | 写入 `ANTHROPIC_API_KEY` | ❌ SDK 无法读取，认证失败 |
| Proxy 用户 | 写入 `ANTHROPIC_AUTH_TOKEN` | ❌ SDK 无法读取，认证失败 |
| OAuth 用户 | 写入 `CLAUDE_CODE_OAUTH_TOKEN` | ✅ 正常工作 |

## 二、修正方案设计

### 2.1 核心原则

**统一入口原则**：所有 Token 类型最终都必须写入 `CLAUDE_CODE_OAUTH_TOKEN`

```
┌─────────────────┐     ┌──────────────────────┐     ┌─────────────────┐
│  OAuth Token    │────▶│                      │────▶│                 │
│  API Key        │────▶│ CLAUDE_CODE_OAUTH_   │────▶│  claude-agent-  │
│  Proxy Token    │────▶│ TOKEN (统一入口)      │────▶│  sdk            │
└─────────────────┘     └──────────────────────┘     └─────────────────┘
```

### 2.2 Token 类型识别规则

| 类型 | 前缀特征 | 原生变量 | 附加要求 |
|------|----------|----------|----------|
| OAuth | `sk-ant-oat01-`, `sk-ant-oat` | `CLAUDE_CODE_OAUTH_TOKEN` | 无 |
| API Key | `sk-ant-api`, `sk-` | `ANTHROPIC_API_KEY` | 无 |
| Proxy | `pc_`, `ccr-` | `ANTHROPIC_AUTH_TOKEN` | 必须设置 `ANTHROPIC_BASE_URL` |

### 2.3 优先级策略

```
1. CLAUDE_CODE_OAUTH_TOKEN (最高优先级)
2. ANTHROPIC_AUTH_TOKEN (Proxy/Enterprise)
3. ANTHROPIC_API_KEY (直接计费)
4. macOS Keychain (仅 OAuth)
```

#### 新增函数

```python
def get_token_type(token: str | None) -> str:
    """
    检测 Token 类型。

    Returns:
        "oauth" | "api_key" | "proxy" | "unknown"
    """
    if not token:
        return "unknown"

    if token.startswith("sk-ant-oat01-") or token.startswith("sk-ant-oat"):
        return "oauth"
    elif token.startswith("sk-ant-api") or (token.startswith("sk-") and "oat" not in token):
        return "api_key"
    elif token.startswith("pc_") or token.startswith("ccr-"):
        return "proxy"
    return "unknown"


def apply_auth_env(token: str) -> str:
    """
    统一设置认证环境变量。

    关键点：SDK 只读取 CLAUDE_CODE_OAUTH_TOKEN，
    因此所有 token 类型都必须写入此变量。

    Returns:
        Token 类型字符串
    """
    token_type = get_token_type(token)

    # 清理潜在冲突变量
    for key in ("CLAUDE_CODE_OAUTH_TOKEN", "ANTHROPIC_API_KEY", "ANTHROPIC_AUTH_TOKEN"):
        os.environ.pop(key, None)

    # 核心：统一写入 SDK 读取的变量
    os.environ["CLAUDE_CODE_OAUTH_TOKEN"] = token

    # 同时设置类型对应的原生变量（用于日志/调试/SDK env 传递）
    if token_type == "api_key":
        os.environ["ANTHROPIC_API_KEY"] = token
    elif token_type == "proxy":
        os.environ["ANTHROPIC_AUTH_TOKEN"] = token

    return token_type


def is_api_key_mode() -> bool:
    """检查当前是否使用 API Key 模式。"""
    token = get_auth_token()
    return get_token_type(token) == "api_key"


def validate_proxy_config() -> tuple[bool, str]:
    """
    验证 Proxy 配置完整性。

    Returns:
        (is_valid, error_message)
    """
    token = get_auth_token()
    if get_token_type(token) != "proxy":
        return True, ""

    base_url = os.environ.get("ANTHROPIC_BASE_URL")
    if not base_url:
        return False, "Proxy token detected but ANTHROPIC_BASE_URL is not set"
    return True, ""
```

def require_auth_token() -> str:
    """获取认证 Token，失败则抛出异常。"""
    token = get_auth_token()
    if not token:
        error_msg = (
            "No authentication token found.\n\n"
            "Auto Claude supports:\n"
            "  1. OAuth Token (recommended):\n"
            "     Run: claude setup-token\n\n"
            "  2. API Key (direct billing):\n"
            "     Set ANTHROPIC_API_KEY in .env\n"

            "  3. Proxy/Enterprise:\n"
            "     Set ANTHROPIC_AUTH_TOKEN + ANTHROPIC_BASE_URL\n"
        )
        raise ValueError(error_msg)
    return token

## 六、风险评估

### 6.1 R_eff 对比

| 方案 | R_eff | 状态 |
|------|-------|------|
| 原方案 | 0.30 | ❌ 致命缺陷 |
| **优化方案** | **0.85** | ✅ 推荐 |

### 6.2 风险缓解

| 风险 | 缓解措施 |
|------|----------|
| API Key 意外高额费用 | 启动时明确警告 + 建议设置预算 |
| Proxy 误直连官方 | 强制校验 `ANTHROPIC_BASE_URL`，缺失则阻断 |
| 多 Token 冲突 | `apply_auth_env()` 清理冲突变量 |

## 附录：决策记录 (DRR)

**决策**: 采用 H2 统一入口方案

**理由**:
1. 原方案 H1 存在根本性 SDK 兼容问题
2. H2 方案 R_eff 最高 (0.85)
3. 最小代码侵入，保持架构稳定

**后果**:
1. 所有 Token 类型都能正常工作
2. 需要用户确认选择此方案后实施
