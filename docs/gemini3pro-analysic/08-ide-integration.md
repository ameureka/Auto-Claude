# 08. IDE 集成与开发者体验 (IDE & DX)

## 1. 概述
Auto-Claude 虽然拥有独立的 GUI，但其设计核心是**“开发者原位协作”**。它通过标准的工程规范文件和深度终端模拟，试图消除 AI 工具与传统 IDE（如 VS Code, Cursor）之间的缝隙。

## 2. Claude-Native 规范 (`CLAUDE.md`)

项目根目录的 `CLAUDE.md` 是连接 AI 与代码库的“母港协议”：
- **引导性**: 为 `claude-code` CLI 提供项目全景视图。
- **标准化**: 定义了环境配置、Spec 运行、构建管理及测试命令的统一入口。
- **作用**: 确保任何接入该项目的 AI 代理（包括 Auto-Claude 内部蜂群）都能瞬间获得“资深员工”级的操作常识。

## 3. 深度终端集成 (PTY-based DX)

系统通过 `node-pty` 实现了一套工业级的虚拟终端环境：
- **实时同步**: UI 的 Terminal 窗口不是简单的日志显示，而是与 PTY 进程全双工绑定的真实 shell。
- **上下文自动注入**: 当开发者在 UI 切换任务时，主进程会通过 PTY Stdin 自动写入任务元数据，实现“一键同步上下文”。
- **Session 恢复**: 支持捕获并恢复 `claude-code` 的特定 Session ID，确保开发过程不中断。

## 4. 隔离式开发工作流

### 4.1 Git Worktree 协作
- **无感切换**: AI 在 `.worktrees/` 下闷头干活，开发者在主目录用 VS Code 继续写代码。
- **热更新隔离**: 这种物理隔离避免了 AI 修改代码触发 IDE 频繁 HMR（热更新）导致的页面白屏或闪烁。

### 4.2 审查与合并视图
- **Review Window**: 提供一键跳转到 Worktree 的能力，方便开发者在本地 IDE 中直接验证 AI 的产出。
- **Merge Preview**: 在合并前展示 JSON 格式的语义冲突分析，让“代码合并”变成“意图对齐”。

## 5. 总结
Auto-Claude 的 DX 设计哲学是**“尊重但不依赖”**：
- 它**尊重**开发者的现有工具链（提供 CLI 和 Worktree）。
- 它**不依赖**特定的 IDE 插件（通过标准协议和终端模拟实现通用性）。
这种设计使其成为一个即插即用、且对工程环境高度友好的“蜂群式”副驾驶。
