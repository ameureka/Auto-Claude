# 核心概念：任务与 Worktree

理解 Auto-Claude 的核心工作机制。

---

## 什么是 Git Worktree？

Git Worktree 是 Git 的一项功能，允许从同一个仓库创建多个独立的工作目录。

```
传统 Git 工作流：
┌─────────────────────────────────────┐
│  项目目录 (只能在一个分支上工作)     │
│  - 切换分支前必须 commit 或 stash   │
│  - 同时只能开发一个功能             │
└─────────────────────────────────────┘

使用 Git Worktree：
┌─────────────────────────────────────┐
│  主项目目录 (main分支)              │
└─────────────────────────────────────┘
            │
    ┌───────┼───────┐
    ▼       ▼       ▼
┌──────┐ ┌──────┐ ┌──────┐
│任务A │ │任务B │ │任务C │
│分支  │ │分支  │ │分支  │
│woktree│ │woktree│ │woktree│
└──────┘ └──────┘ └──────┘
  独立目录  独立目录  独立目录
```

**简单理解**：Worktree 就是从同一个 Git 仓库"克隆"出多个独立的工作目录，每个目录可以在不同分支上工作，**互不干扰**。

---

## 为什么 Auto-Claude 使用 Worktree？

| 好处 | 说明 |
|------|------|
| **任务隔离** | 每个 AI 任务在独立目录工作，不会影响你的主代码 |
| **并行执行** | 可以同时运行多个任务，各自独立开发 |
| **安全审查** | AI 的改动在独立分支，你可以审查后再合并 |
| **不怕出错** | 如果 AI 搞砸了，直接删除 worktree 就行 |

## 任务与窗口的关系

```
┌─────────────────────────────────────────────────────────┐
│                    Auto-Claude 界面                      │
├─────────────────────────────────────────────────────────┤
│  看板 (Kanban)                                           │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │
│  │Backlog │ │Progress│ │AI Review│ │Human   │ │Done    │ │
│  │        │ │        │ │        │ │Review  │ │        │ │
│  │ 任务1  │ │ 任务2  │ │        │ │        │ │ 任务3  │ │
│  │ 任务4  │ │        │ │        │ │        │ │        │ │
│  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘ │
├─────────────────────────────────────────────────────────┤
│  代理终端 (Agent Terminals)                              │
│  ┌──────────────────┐ ┌──────────────────┐              │
│  │ 任务2 终端窗口   │ │ 任务4 终端窗口   │              │
│  │ (正在执行中)     │ │ (正在执行中)     │              │
│  │ > 分析代码...    │ │ > 编写功能...    │              │
│  │ > 创建规格...    │ │ > 运行测试...    │              │
│  └──────────────────┘ └──────────────────┘              │
└─────────────────────────────────────────────────────────┘
```

### 对应关系

| 概念 | 对应关系 |
|------|----------|
| **1个任务** | = 1个看板卡片 = 1个 Worktree = 1个终端窗口 |
| **创建任务** | 系统自动创建 worktree + 启动 AI 代理 |
| **终端窗口** | 显示该任务的 AI 执行过程 |
| **任务完成** | 可选择合并代码到主分支 |

## 完整流程示例

```
1. 你创建任务「添加用户登录功能」
         ↓
2. Auto-Claude 自动：
   - 创建分支: feature/add-user-login-xxx
   - 创建 worktree: ~/.auto-claude-worktrees/项目名/任务ID/
         ↓
3. 在「代理终端」看到独立窗口，显示 AI 正在：
   - 分析需求
   - 编写规格
   - 实现代码
   - 运行测试
         ↓
4. 完成后在「Worktrees」页面：
   - 审查代码变更
   - 选择「Merge」合并到主分支
   - 或「Delete」放弃更改
```

## 常见问题

### Q: 多个任务会有多个窗口吗？

**A: 是的！** 每个正在执行的任务都有自己的终端窗口，可以同时查看多个任务的进度。

### Q: 任务完成后代码在哪里？

**A:** 代码在独立的 worktree 目录中（`~/.auto-claude-worktrees/`），需要通过「Worktrees」页面审查并合并到主分支。

### Q: 为什么不直接改我的代码？

**A:** 这是 **安全设计**！AI 可能出错，隔离到 worktree 后：
- 你的主代码始终保持干净
- 可以先审查再决定是否采用
- 不满意可以一键删除

### Q: Worktree 占用磁盘空间吗？

**A:** 占用很少。Git Worktree 使用硬链接复用 `.git` 数据，只存储实际的文件变更。
